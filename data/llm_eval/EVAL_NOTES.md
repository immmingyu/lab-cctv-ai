# LLM 질의응답 평가 메모

LLM 답변 평가의 채점 방식을 기록한다. 빈칸(`____`)은 채점자가 채운다.

## 공통 채점 기준
- 시트 열: `A 정확(O/△/X)`, `A 지어냄(Y/N)`, `B 정확(O/△/X)`, `B 지어냄(Y/N)`, `메모`
- 기호는 정확히 `O`, `△`, `X`, `Y`, `N`만 쓴다. `score_eval`이 다른 값을 오류로 알린다.
- 점수 환산: O = 1, △ = 0.5, X = 0 (`src/experiments/llm_eval/score_eval.py` `SCORE`). 지어냄은 Y인 문항 수를 따로 센다.
- **O / △ / X와 지어냄의 판정 기준 (문장으로):** 저장소와 작업 기록 어디에도 문장으로 적힌 기준이 없다. 개발용 평가 때 쓴 기준을 **시험용 채점 전에** 아래에 적고, 두 평가에 같은 기준을 쓴다.

  - △: ____

  - 지어냄 Y: ____

## 알려진 한계 (두 평가 공통)
- "계산 결과 넣음" 조건은 해당 기록이 없으면 LLM을 부르지 않고 코드가 고정 문장으로 답한다. 이런 답은 문장 모양을 보고 조건을 짐작할 수 있다.
  - 시험용 12문항에서는 이런 답이 2개다 (어느 문항인지는 채점 후 `raw.csv`의 `LLM호출` 열로 확인).
- 채점자가 개발자 본인이면, 답 문체를 보고 조건을 짐작할 가능성을 완전히 없앨 수는 없다.
- LLM temperature는 0.3이라, 다시 생성하면 답이 달라질 수 있다. 결과는 생성 1회분이다.

## 채점 후 집계
채점한 시트를 키 폴더에 넣고 집계한다:
```
python -m src.experiments.llm_eval.score_eval data/llm_eval/run_20261111_235156_grounding_ollama_exaone3.5-7.8b --sheet <채점한 시트 이름>
```
